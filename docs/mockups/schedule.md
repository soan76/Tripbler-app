# 일정 화면과 일정 추가·저장 (설계 · 목업)

작성: 2026-11-27 · 상태: 설계와 HTML 목업, 앱에는 아직 구현하지 않음 · 함께 보는 파일: [schedule.html](schedule.html) (눌러 볼 수 있는 목업)

목업 `schedule.html`은 샘플 데이터와 화면 동작만으로 만들었다(실제 저장·알림·지도 연동 없음, 새로 고침하면 처음 상태). 확인할 흐름: 빈 상태 → 입력 → 저장된 타임라인 → 수정·삭제 → 다음 일정 추가. 저장 실패·알림 권한 같은 연동 처리는 이 문서(3절)에만 적는다.

## 1. 범위

- 포함: 일정 화면(빈 상태·세로 타임라인), 일정 입력 카드(제목·날짜·시간·장소·알림·메모), 저장·취소, 저장한 일정 수정·삭제, 기기 저장(앱 재실행 후 유지), 지도에서 장소 고르기, 기기 알림 예약과 권한·실패 처리.
- 제외: 하단 방사형 메뉴 재배치(일정 버튼 자리 포함), 면세 기능. 일정 화면으로 들어가는 길은 메뉴 작업에서 정한다. 그전까지 앱에서는 임시 경로(개발용)로 연다.
- 제외(다음 단계): 반복 일정, 여러 날 일정, 서버 동기화.

## 2. 화면

### 2-1. 빈 상태

- 위 제목 줄 "일정".
- 화면 가운데에 `+` 버튼(지름 72, 아이콘만 있는 버튼이라 원형 허용)과 그 아래 "첫 일정을 추가해 보세요".
- `+`를 누르면 입력 카드가 열린다.

### 2-2. 저장된 일정: 세로 타임라인

- 처음에는 날짜·시간 순(이른 것이 위)으로 세로 타임라인을 그린다. 순서는 날짜·시간과 따로 저장하므로 사용자가 바꿀 수 있다(아래 "순서 바꾸기"). **오른쪽에 점 노드**(지름 18, 강조색), **왼쪽에 제목**.
- 왼쪽 글자: 위 작은 줄에 시각(날짜가 바뀌는 첫 일정만 "11월 28일 (토) · 오전 8:00", 나머지는 "오후 2:30"), 가운데 제목(굵게), 아래 장소명(있으면).
- 점과 점 사이는 실선(2, 강조색)으로 잇는다. 지난 일정은 속이 빈 점과 흐린 글자로 보인다.
- **제목이나 점을 누르면 수정 화면**이 아래에서 올라온다(2-4). 누를 수 있는 영역은 제목 줄 전체와 점 둘레 48×48.
- **마지막 일정 아래**에 약 100 길이의 **점선**(2, 외곽선 색)을 잇고, 끝에 `+` 노드(지름 40 테두리 원, 누르는 영역 48)와 왼쪽에 "다음 일정을 추가해 보세요"를 둔다. 안내 글자나 `+`를 누르면 입력 카드가 열린다.
- 다음 일정 입력 카드의 기본값: 마지막 일정이 아직 지나지 않았으면 그 날짜·그다음 시간, 아니면 2-3의 기본값.
- 저장 동작(새 일정이 맨 끝에 붙을 때): 카드가 닫힘 → 마지막 일정 아래 점선이 위에서부터 실선으로 채워짐(약 0.35초) → 그 자리에 새 점이 커지며 나타나고 제목이 옆에서 들어옴 → 새 일정 아래에 점선과 `+`가 다시 자람. 새 일정이 중간 시각이면 시간순 자리에 넣고 점과 제목만 나타나게 한다. 애니메이션 줄이기 설정에서는 움직임 없이 바로 바뀐다.
- 저장 뒤 새 일정이 화면 밖이면 그 줄이 보이게 스크롤한다. 일정이 많으면 타임라인 전체가 세로로 스크롤된다(`+` 노드도 목록 끝에 함께 있음).
- **취소**하면 타임라인과 스크롤 위치를 그대로 둔다.
- **순서 바꾸기(길게 눌러 끌기)**: 일정 줄을 약 0.45초 누르면 그 줄이 살짝 떠오른다(1.02배, 그림자, 연결선 숨김, 짧은 진동). 위아래로 끌면 잡은 줄의 가운데가 지나간 줄들이 0.2초 동안 부드럽게 비켜나 빈자리를 보여 준다. 놓으면 그 자리로 순서가 바뀌고 줄이 잠깐 강조된다. 날짜·시간은 바뀌지 않는다. 화면 위·아래 끝 가까이 끌면 목록이 따라 스크롤된다.
  - 누르고 0.45초 안에 8px 넘게 움직이면 끌기가 아니라 스크롤로 본다. 짧게 누르면 지금처럼 수정 화면이 열린다. 끌기를 마친 뒤에는 수정 화면이 열리지 않는다.
  - 날짜 표시는 줄의 날짜가 바로 위 줄과 다를 때만 붙는다(순서를 바꾸면 날짜가 섞일 수 있다).
  - 새 일정은 지금 순서에서 처음으로 더 늦은 일정 앞에 넣는다. 수정에서 날짜·시간을 바꾸면 같은 규칙으로 자리를 다시 찾고, 바꾸지 않으면 자리를 그대로 둔다.
  - 끄는 동안 낭독기·키보드 사용자를 위한 대안(위로·아래로 옮기기 동작)은 앱 구현 때 넣는다.
- 알림 상태 표시(권한 없음·예약 실패)는 수정 화면의 알림 줄과 제목 아래 작은 줄에 둔다(3-3).

### 2-3. 입력 카드

화면 아래에서 올라오는 카드(바텀 시트 모양, 위 둥글기 4). 항목 사이에 구분선. 각 항목 왼쪽에 아이콘, 오른쪽에 값. 원형 버튼 대신 **평평한 아이콘·텍스트 영역**(전체가 누를 수 있는 48 이상 높이의 줄).

| 순서 | 항목 | 입력 | 규칙 |
| --- | --- | --- | --- |
| 1 | 제목 | 한 줄 텍스트 | **필수**. 앞뒤 공백 제거 후 1~50자. 비었으면 저장 때 "제목을 입력해 주세요"를 제목 아래에 표시하고 제목으로 초점 이동 |
| 2 | 날짜 | 누르면 바로 아래에 달력이 펼쳐짐 | 기본값 오늘. 달력에서 날짜 하나 고름(달 넘기기 가능) |
| 2 | 시간 | 누르면 바로 아래에 휠 피커가 펼쳐짐 | 오전/오후 · 시(1~12) · 분(00~59, 1분 단위) 세 칸을 각각 위아래로 스크롤. 기본값 "지금 다음 정시"(예: 14:20 → 오후 3:00), 오늘이 지나면 오전 9:00 |
| 3 | 장소 | 직접 입력 또는 왼쪽 지도 아이콘 | 선택. 지도 아이콘 → 지도에서 고르기 → 장소명·주소·좌표를 돌려받아 채움. 직접 입력하면 좌표 없음 |
| 4 | 알림 | 누르면 선택지 | 없음 · 정시 · 5분 전 · 10분 전 · 30분 전 · 1시간 전. 기본값 "없음" |
| 5 | 메모 | 여러 줄 텍스트 | 선택. 최대 500자, 3줄 높이에서 시작해 늘어남 |
| 6 | 하단 | `취소` \| `저장` | 같은 폭 두 버튼(둥글기 4). 저장은 강조색 |

- 날짜·시간은 평평한 아이콘·텍스트 줄 두 개("[달력 아이콘] 11월 27일 (금) · 오늘 ⌄", "[시계 아이콘] 오후 3:00 ⌄")를 위아래로 둔다.
- **펼치고 접기**: 선택기(달력·휠)는 처음에 숨겨 둔다. 줄을 누르면 그 줄 바로 아래로 미끄러지듯 펼쳐지고(약 0.28초), 같은 줄을 다시 누르면 위로 접혀 사라진다. 펼치고 접는 동안 아래 항목(장소·알림·메모)도 함께 부드럽게 밀리고 당겨진다. 날짜와 시간 선택기는 따로 펼친다. 펼친 줄은 강조색 테두리·글자와 위로 향한 화살표로 표시한다.
- **고른 값은 바로 표시**: 달력에서 날짜를 누르거나 휠을 멈추면 줄의 값이 바로 바뀐다. 선택기는 자동으로 닫히지 않는다. 접었다 다시 펼쳐도 고른 날짜·시간이 그대로다(값은 작성 상태에 있다).
- **선택 영역 모양**: 별도 카드 배경·테두리·그림자 없이 입력 카드 바탕에 그대로 이어진다. 휠은 칸 높이 40, 다섯 칸이 보이고 가운데 칸이 고른 값(굵게)이며, 위아래 끝은 흐리게 사라진다. 칸을 누르면 그 값으로 굴러간다.
- 카드를 새로 열거나 수정 화면을 열 때는 선택기가 접힌 상태로 시작한다. 애니메이션 줄이기 설정에서는 움직임 없이 바로 펼치고 접는다.
- 알림 시각이 이미 지났으면(예: 10분 뒤 일정에 30분 전 알림) 알림 줄 아래에 "알림 시각이 지나 알림을 보낼 수 없어요"를 보이고 알림을 예약하지 않는다. 일정 저장은 막지 않는다.

### 2-4. 일정 수정 화면

- 저장한 일정의 제목이나 점을 누르면 열린다. 구성은 입력 카드(2-3)와 같고, 저장한 값이 채워져 있다(장소를 지도에서 골랐으면 주소·좌표도).
- 다른 점은 세 가지다.
  - 머리글 "일정 수정"과 **왼쪽 위 뒤로 가기**(48×48).
  - 하단 버튼이 `삭제 | 수정`(같은 폭, 둥글기 4). 삭제는 오류색 테두리, 수정은 강조색.
  - 어두운 바깥을 누르면 뒤로 가기와 같다.
- **뒤로 가기**: 바꾼 게 없으면 바로 닫는다. 바꾼 게 있으면 "수정한 내용을 버릴까요?"(`계속 수정` / `버리기`)를 묻는다. 시스템 뒤로 가기도 같다.
- **수정**: 제목 검사(2-3과 같음) → 기기에 저장 → 닫는다. 날짜·시간을 바꿨으면 자리를 다시 찾는다(2-2 순서 바꾸기). 날짜·시간을 바꿔 자리가 옮겨지면 그 줄이 보이게 스크롤하고 잠깐 강조한다. 저장에 실패하면 화면을 닫지 않고 입력값을 그대로 둔다. 알림을 바꿨으면 예전 알림을 지우고 새로 예약한다.
- **삭제**: "이 일정을 삭제할까요? 삭제한 일정은 되돌릴 수 없어요."(`취소` / `삭제`)로 한 번 확인 → 목록과 기기 저장소에서 지우고 예약된 알림도 지운다. 마지막 일정을 지우면 빈 상태로 돌아간다.

## 3. 동작

### 3-1. 취소·저장

- **취소**: 일정을 만들지 않고 카드를 닫는다. 입력한 게 있으면 "작성 중인 내용을 버릴까요?"를 한 번 묻는다.
- **저장**:
  1. 제목 검사 → 실패하면 멈추고 표시.
  2. 기기 저장소에 쓴다 → 실패하면 카드를 닫지 않고 입력값을 그대로 두며 "저장하지 못했어요. 다시 시도해 주세요"를 카드 위에 표시.
  3. 저장에 성공하면 카드를 닫고 타임라인에 날짜·시간 순으로 넣는다(움직임은 2-2).
  4. 알림을 골랐으면 그다음 알림을 예약한다(3-3). 알림 예약이 실패해도 일정은 저장된 상태로 둔다.
- 저장 버튼은 저장 중에 다시 눌리지 않는다(진행 표시).

### 3-2. 지도에서 장소 고르기

- 장소 줄의 지도 아이콘 → **장소 고르기 화면**(지도 화면과 같은 지도·검색창을 쓰는 별도 화면, 위에 "장소 고르기"와 닫기)을 연다.
- 검색하거나 지도 결과를 눌러 장소 카드가 뜨면 카드 아래 버튼이 "길찾기" 대신 **"이 장소 선택"**이다.
- 선택하면 `PlaceModel`의 `name`·`address`·`latitude`·`longitude`(·`id`)를 돌려주고 일정 카드로 돌아와 장소 줄을 채운다. 닫기·뒤로 가기로 돌아오면 장소는 바뀌지 않는다.
- **작성 내용 유지**: 입력 중인 내용은 화면 위젯이 아니라 작성 상태(`ScheduleDraftNotifier`)에 있으므로 지도를 다녀와도 그대로다. 앱이 백그라운드로 갔다 와도 같다.
- 지도 탭의 검색 결과·선택과는 섞지 않는다(장소 고르기는 자기 검색 상태를 쓴다).
- 지도 검색은 로그인이 필요하다(지금 규칙). 로그인 전이면 장소 고르기 화면 검색창에 지금과 같은 로그인 안내를 보이고, 장소는 직접 입력할 수 있다.

### 3-3. 알림

- 알림을 "없음" 외로 고르고 저장할 때 처음이면 알림 권한을 묻는다(Android 13 이상, iOS).
- 권한 허용 → 일정 시작 − 고른 분에 기기 알림 예약. 알림 내용: 제목 "15:00 루브르 박물관", 본문 "30분 뒤 시작해요 · 장소명".
- 권한 거부 → 일정은 저장하고 알림 상태를 "알림 못 함(권한 없음)"으로 둔다. 타임라인 제목 아래와 수정 화면에 "알림 권한이 꺼져 있어요 · 설정 열기"를 보인다.
- 예약 실패(시스템 오류 등) → 일정은 저장하고 "알림 예약에 실패했어요 · 다시 시도"를 보인다.
- 앱을 다시 켤 때 저장된 일정의 알림 예약을 확인하고, 빠진 것은 다시 예약한다(기기 재시작으로 지워진 경우 등).
- 정확한 시각 알림(Android 정확한 알람 권한)은 쓰지 않고 기기가 허용하는 범위에서 예약한다. 몇 분 늦을 수 있다는 점을 안내 문구에 적지 않되, 테스트에서 확인한다(정할 것 7).

## 4. 데이터

```text
ScheduleItem
  id            String   (생성 시각 기반 고유값)
  title         String   (1~50자)
  startsAt      DateTime (날짜 + 시·분, 1분 단위, 기기 현지 시각)
  place         ScheduledPlace?   name, address?, latitude?, longitude?, placeId?
  alarm         ScheduleAlarm     none | atStart | before(minutes: 5|10|30|60)
  alarmStatus   scheduled | off | denied | failed | passed
  memo          String   (0~500자)
  createdAt     DateTime
```

- 순서: 사용자가 끌어 바꾼 순서는 JSON 목록의 순서로 저장한다(날짜·시간과 따로). 처음 저장·새 일정 넣기 규칙은 2-2 "순서 바꾸기"를 따른다. 지금 앱 구현은 읽을 때 시간순으로 정렬하므로, 순서 바꾸기를 넣을 때 이 정렬을 함께 바꿔야 한다(목업만, 앱 미구현).
- 저장: `shared_preferences`의 한 키 `schedule.items.v1`에 JSON 목록. 버전 번호를 두어 나중에 형식을 바꿀 수 있게 한다. 읽을 때 형식이 틀린 항목은 버리고 나머지는 살린다(지금 `LocalStorageService`처럼 안전하게 파싱).
- 다음 저장이 덮어쓰면 잃을 저장값은 원래 문자열을 백업한다. 대상은 해석하지 못한 값(JSON 깨짐, 다른 버전, 목록 아님), 일부 항목을 버린 값, 살린 항목의 값이 바뀐 값(제목·메모 잘림, 제목 앞뒤 공백 제거, 모르는 필드, 읽지 못한 장소 필드)이다. 키 순서, 정수/실수 좌표, null 필드, 생략한 메모·알림 기본값, 같은 시각의 다른 날짜 표기는 바뀐 것으로 보지 않는다.
- 백업은 `schedule.items.v1.backups` 한 키에 `[{"savedAt": ISO 시각, "raw": 원래 문자열}]`(오래된 것부터)로 최근 3개까지 둔다. 같은 문자열은 다시 넣지 않고, 넘치면 가장 오래된 것부터 지운다. 백업을 쓰지 못하면 불러오기 실패로 두어 추가를 막는다(다시 시도 가능). 개발 중에 쓰던 단일 키 `schedule.items.v1.backup`은 읽지도 지우지도 않는다. 백업을 되살리는 화면은 아직 없다(지금 앱 구현 기준. 화면을 만들 때의 개수 규칙은 아래 "개수"를 따른다).
- **보관함·백업 화면(목업만, 앱 미구현)**: [schedule-backup.html](schedule-backup.html). 샘플 데이터로 정상·일부 손상·전체 손상·버전 불일치·읽지 못한 보관 여러 개·불러오기 실패·빈 화면을 고를 수 있고, 모든 동작은 목업 안에서만 바뀐다. 일정 화면 위 오른쪽에 보관함·백업 아이콘(48)을 둔다(앱에서는 일정 탭일 때 공통 상단 바 `AppTopBar`의 오른쪽 동작으로 넣을지 정한다).
  - **보관함(다음 단계)**: 타임라인 일정을 누르면 지금과 같이 수정 화면(2-4)이 열리고, 그 안에 `보관함으로 이동` 줄을 둔다. 옮기면 타임라인에서 빠진다. 보관함 목록은 일정 시각·제목·보관 시각, 누르면 `삭제 | 다시 꺼내기`. 자동으로 지우지 않는다. 보관한 일정을 따로 저장해야 하므로 저장 형식이 바뀐다(백업의 "바뀐 값" 판단·버전 처리를 함께 정한다).
  - **백업 위치**: `기기 백업`(이 기기에만, 앱을 지우면 사라짐)과 `서버 백업`(다음 단계)을 나눠 보인다. 서버 백업은 로그인해야 쓸 수 있고(로그인 전에는 안내와 `로그인`), 처음 백업할 때 일정 제목·날짜·시간·장소·메모가 서버로 간다는 동의(`동의하고 백업`)를 받는다. 서버 API와 보안 점검이 필요하다(`backend/`).
  - **백업 목록 자체가 깨졌을 때**: 목록 저장값(`schedule.items.v1.backups`)을 읽지 못한 부분(전체, 형식이 틀린 항목, 겹친 id)이 있으면, 다음 쓰기 전에 원래 문자열을 `schedule.items.v1.backups.damaged`(문자열 목록, 같은 값은 한 번만)에 남긴다. 남기지 못하면 목록을 쓰지 않는다(앱 구현 2026-11-28).
  - **개수**: 직접 백업은 위치마다 최근 3개까지 둔다. **읽지 못해 보관한 백업은 개수에 세지 않고, 사용자가 직접 지우기 전에는 지우지 않는다**(하나뿐인 원래 내용일 수 있다). 직접 백업이 3개일 때 `지금 백업`은 가장 오래된 직접 백업만 지워진다고 먼저 확인한다.
  - **백업 동작**: `지금 백업`은 지금 일정의 복사본을 만든다. 일정이 없거나, 지금 일정이 마지막 직접 백업과 같거나("지금 일정이 마지막 직접 백업과 같아요"), 일정을 불러오지 못한 상태면 꺼진다. 줄마다 `삭제`, 위에 `전체 삭제`. 줄에는 보관 시각과 "직접 백업" / "읽지 못해 보관" 표시, "되살릴 수 있는 일정 N개 · 읽지 못한 항목 M개" 또는 버전 불일치·손상 문구.
  - **읽지 못한 일정 알림**: 아직 확인하지 않은 "읽지 못해 보관" 백업이 있으면 일정 화면 위에 "읽지 못한 일정이 있어요" + `확인`(기기 백업 목록으로) + 닫기. 확인·닫기·그 백업에서 되살리기를 하면 그 백업은 확인한 것으로 기기에 기억해, 앱을 다시 켜도 다시 띄우지 않는다. 새로 읽지 못한 값이 생기면 다시 띄운다.
  - **복원**: 백업을 누르면 선택 칸 목록. 지금 일정에 이미 있으면 "이미 있음", 보관함에 있으면 "보관함에 있음"으로 표시하고 처음엔 고르지 않는다. `선택한 일정 되살리기 (N)`으로 고른 것만 더하고(이미 있는 것과 겹치면 새 id), 복원한 뒤에도 백업은 남는다. 읽지 못한 항목은 개수만 보인다.
  - **불러오기 실패**: 일정을 불러오지 못한 상태(일정 화면에 "일정을 불러오지 못했어요 · 다시 시도")에서는 백업 만들기와 되살리기를 막는다("일정을 불러온 뒤에 되살릴 수 있어요"). 되살린 목록을 저장하면 읽지 못한 기존 저장값을 덮어쓰기 때문이다.
  - **삭제 확인창**: 무엇이 지워지는지(제목 또는 위치·시각)와 영향을 적는다 — 지금 일정·보관함은 바뀌지 않음, 그 백업에만 있어 더는 되살릴 수 없게 되는 일정 수와 제목, 읽지 못해 보관한 원래 내용도 사라짐, 되돌릴 수 없음.
  - **터치 영역**: 위치 전환·`지금 백업`·`전체 삭제`·확인창 버튼 모두 높이 48.
  - **앱 구현과 다른 점(구현 때 바꿀 것)**: 지금 저장소는 읽지 못한 값 백업만 최근 3개로 두고 넘치면 가장 오래된 것을 지운다 → 위 "개수" 규칙으로 바꾼다. 지금은 손상과 새 버전 형식을 구분하지 않는다 → 저장값의 버전이 지금보다 높으면 "새 버전 형식"으로 따로 표시한다. 알림 확인 기록과 직접 백업 저장 키는 새로 정한다.
- 제목·메모 길이는 입력칸과 같이 글자(grapheme) 단위로 센다. 읽을 때 한도를 넘은 값은 버리지 않고 글자 기준으로 잘라 살린다(원본은 위 백업에 남는다).
- 시각은 기기 현지 시각으로 저장하고, 여행지 시간대 처리(해외 시간대가 바뀔 때)는 다음 단계에서 정한다(정할 것 7).
- 개인정보: 일정 제목·메모를 로그에 남기지 않는다.

## 5. 구조 (Riverpod, AGENTS.md 기준)

| 계층 | 파일(안) | 책임 |
| --- | --- | --- |
| 모델 | `lib/models/schedule/schedule_item.dart` | `ScheduleItem`, `ScheduledPlace`, `ScheduleAlarm`, JSON 변환 |
| Service | `lib/services/schedule/schedule_storage_service.dart` | `shared_preferences` 읽기·쓰기, 안전한 파싱 |
| Service | `lib/services/schedule/schedule_notification_service.dart` | 권한 확인·요청, 예약·취소, 재예약. 패키지 의존성은 이 파일에만 둔다 |
| 상태 | `lib/providers/schedule/schedule_provider.dart` | `ScheduleNotifier`(`NotifierProvider`): 목록 불러오기, 정렬, 추가·수정·삭제, 알림 상태 갱신 |
| 상태 | `lib/providers/schedule/schedule_draft_provider.dart` | `ScheduleDraftNotifier`: 작성 중 입력값(새 일정 또는 수정할 일정 id와 처음 값), 검사, 저장 진행·실패. 지도 다녀와도 유지 |
| 화면 | `lib/screens/schedule_screen.dart` | 빈 상태·세로 타임라인, 입력·수정 화면 열기 |
| 화면 | `lib/screens/place_picker_screen.dart` | 지도에서 장소 고르기, `ScheduledPlace` 반환 |
| 위젯 | `lib/widgets/schedule/` | 입력 카드, 날짜·시간 줄과 펼침 선택기(달력, 오전/오후·시·분 휠), 알림 선택, 타임라인 줄(점·연결선·끝의 점선과 `+` 노드). 입력 카드는 추가·수정 공용 |

- Service는 provider로 주입하고 테스트에서 override한다(지금 구조와 같음).
- 화면은 표시와 입력만, 저장·검사·알림은 Notifier와 Service에서 한다.
- 비동기 결과(저장·권한·예약)는 화면이 닫혔거나 작성이 바뀐 뒤 반영하지 않는다(세대 번호 또는 `ref.mounted`).
- 파일 하나 450줄 이하.
- **의존성(확인 필요)**: 기기 알림 예약에는 새 패키지가 필요하다(예: `flutter_local_notifications` + 시간대 처리 `timezone`). 권한은 이미 있는 `permission_handler`를 쓴다. Android 매니페스트(알림 권한, 재부팅 후 재예약)와 iOS 설정이 바뀐다. 구현 전에 사용자 확인을 받는다.

## 6. 사용성·검증

| 확인 | 방법 |
| --- | --- |
| 작은 화면(폭 320, 높이 640) | 카드가 화면 높이의 90%를 넘지 않고, 넘치면 카드 안 스크롤. 선택기를 펼쳐도 휠 세 칸이 가로로 넘치지 않음 |
| 키보드 | 키보드가 열리면 카드가 키보드 위로 올라가고, 초점 둔 칸이 가려지지 않게 스크롤. 하단 `취소 \| 저장`은 키보드 위에 붙음 |
| 큰 글자(1.3·2.0) | 줄이 잘리지 않고 늘어남 |
| 필수 입력 | 제목 비움·공백만 → 저장 안 됨, 안내와 초점 |
| 지도 복귀 | 지도에서 고르기·닫기·뒤로 가기 모두 작성 내용 유지, 고르면 장소명·주소·좌표 채움 |
| 저장 | 저장 → 타임라인 순서·점선이 실선으로 바뀜, 취소 시 화면 유지, 앱 재실행 후 유지, 저장 실패 시 카드 유지·입력값 보존 |
| 날짜·시간 선택기 | 처음 접힘, 누르면 펼침·다시 누르면 접힘, 고르면 값 즉시 표시·선택기 유지, 접었다 펼쳐도 값 유지, 펼칠 때 아래 항목이 함께 이동, 분 00~59 |
| 수정·삭제 | 누르면 값이 채워진 수정 화면, 뒤로 가기(바꾼 것 없음 → 바로 닫힘, 있음 → 버릴지 물음), 수정 → 다시 정렬, 삭제 확인 → 목록·저장소·알림에서 제거, 마지막 일정 삭제 → 빈 상태 |
| 알림 | 권한 허용·거부·영구 거부(설정 열기), 예약 실패, 지난 알림 시각, 재실행 후 재예약 |
| 접근성 | 모든 줄 48 이상, 낭독기 이름("날짜, 11월 27일 금요일, 바꾸려면 두 번 누르기") |

테스트(구현 때): Notifier 단위 테스트(정렬, 검사, 저장 실패 보존, 알림 상태), Service 테스트(손상된 저장값), 위젯 테스트(빈 상태, 카드 열기·취소, 수정·뒤로 가기·삭제 확인, 키보드 높이, 작은 화면), 장소 고르기 반환.

## 7. 정할 것

- 시간 기본값(다음 정시)과 알림 선택지(5·10·30·60분, 정시) 확정.
- 날짜를 펼친 채 시간을 펼치면 날짜 선택기를 자동으로 접을지(지금은 따로 펼침).
- 해외 시간대: 일정 시각을 기기 시각으로 둘지, 여행지 시간대로 둘지.
- Android 알림이 몇 분 늦을 수 있는 방식(정확한 알람 권한 없이)으로 충분한지.
- 일정 화면 진입 경로(메뉴 작업과 함께).
- 삭제를 되돌리기(스낵바 "실행 취소")로 할지, 지금처럼 확인 대화 상자로 할지.
