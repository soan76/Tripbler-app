# 하단 이동 메뉴 3단계

작성: 2026-11-26 · 상태: 구현됨(2026-11-26, 위젯 테스트로 확인, 실기기 미확인) · 함께 보는 파일: [bottom-nav.html](bottom-nav.html) (눌러 보고 끌어 볼 수 있는 프로토타입)

## 1. 목적

지금 하단 메뉴는 작은 고리를 끌면 부채꼴 버튼(환율·지도·번역·AI)이 한 번에 펼쳐진다. 이를 **작은 점 → 현재 화면 아이콘 → 부채꼴 메뉴**의 3단계로 바꾸고, 끄는 만큼 원형 배경이 반원으로 이어서 변하게 한다. 화면을 덜 가리면서, 지금 어느 화면인지와 메뉴가 어디서 나오는지를 손끝에서 알 수 있게 하는 것이 목표다.

- 참고 이미지(2026-11-26 받음)는 반원 배경과 버튼 배치·모양의 참고로만 쓴다. 버튼 크기(64·76)는 지금 `lib/widgets/bottom_tab_bar.dart`와 같고, 버튼 자리는 이미지에 맞춰 조금 올렸다(5절).
- 이미지의 화면 구성(가운데 "오늘" 등)은 가져오지 않는다. 메뉴의 버튼은 지금처럼 환율·지도·번역·AI다.

### 참고 이미지에서 가져온 모양

| 요소 | 모양 |
| --- | --- |
| 반원 배경 | 옅은 청회색 반투명 면, 가는 점선 테두리, 아래는 화면 아래에 붙어 평평 |
| 일반 버튼(환율·지도·번역, 64) | 반투명 회색 원 + 옅은 회색 테두리, 진회색 아이콘. 이름은 원 아래 가장자리에 걸친 흰 꼬리표(지금 앱의 테두리 틈 모양과 같음) |
| 가운데 버튼(AI, 76) | 같은 원 모양, 이름을 원 안 아이콘 아래에 씀 |
| 현재 화면 | 파란 원(지금 앱의 선택색 `Colors.blue`) + 흰 아이콘, 이름 굵게. 가운데 버튼이 현재 화면이면 이름도 흰색 |

## 2. 상태

| 상태 | 보이는 것 | 누르기 | 끌기 |
| --- | --- | --- | --- |
| **점** (기본) | 하단 가운데 반투명 작은 점(지름 10). 터치 영역은 48×48 | 현재 화면 아이콘 상태로 커짐. **어느 화면에서도 촬영하지 않음** | 없음(먼저 눌러 키운다) |
| **현재 화면 아이콘** | 반투명 원형 배경(지름 64) 위에 현재 화면 아이콘과 이름(환율·지도·번역·AI) | 번역 촬영 화면에서만 **사진 촬영**. 그 밖의 화면에서는 아무 일 없음 | 위로 끌면 부채꼴로 펼쳐짐(진행률에 연동) |
| **부채꼴 메뉴** | 바닥이 평평하고 위가 둥근 반원 배경 + 환율·지도·번역·AI 버튼. 현재 화면 버튼 강조 | 다른 화면 버튼: 이동하며 점으로 접힘 · 현재 화면 버튼: 이동 없이 점으로 · 메뉴 바깥: 이동 없이 점으로 | 아래로 끌면 진행률이 줄며 원형으로 돌아옴 |

- 현재 화면 아이콘 상태에서 일정 시간(초안 4초) 아무 입력이 없거나 메뉴 바깥을 누르면 점으로 돌아간다.
  - 예외(2026-11-27 사용자 요청): 번역 화면에서는 점 상태가 없다. 들어오자마자(다른 화면에서 번역 버튼을 골라 들어올 때 포함) 현재 화면 버튼 상태이고, 바깥 누르기·4초 무입력에도 접히지 않는다. 부채꼴에서 바깥을 누르거나 번역을 다시 고르면 현재 화면 버튼 상태로 돌아온다. 번역 화면에서 다른 화면을 고르면 지금처럼 점으로 접힌다. 코드: `BottomTabBar.alwaysShowIcon`(메인 화면이 번역 탭에서만 켠다).
- AI 홈으로는 부채꼴의 AI 버튼으로만 간다. 다른 탭을 다시 누르는 것으로 홈에 가던 지금 규칙("선택된 탭을 다시 누르면 홈")은 **없앤다**. 현재 화면 재선택은 접기만 한다.

## 3. 상태 전환

```
점 ──누르기──▶ 현재 화면 아이콘 ──위로 끌기(진행률 p)──▶ 부채꼴
 ▲                 │  ▲                                  │
 │   바깥 누르기·   │  └──놓기(p < 기준) / 아래로 끌기 ────┘
 │   4초 무입력     │
 └─────────────────┘
 ▲                                                        │
 └── 버튼 선택(이동) · 현재 화면 재선택 · 바깥 누르기 ────────┘  (부채꼴 → 원형 → 점 순서로 접힘)
```

## 4. 제스처 규칙

| 항목 | 초안 값 | 이유 |
| --- | --- | --- |
| 누르기와 끌기 구분 | 손가락이 **8px** 넘게 움직이면 끌기. 끌기로 판정되면 그 손가락을 떼도 누르기(촬영)로 처리하지 않음 | 끌다가 놓을 때 촬영되는 오작동 방지 |
| 완전히 펼치는 거리 | 위로 **120px** = 진행률 1 | 엄지 한 번으로 닿는 거리 |
| 놓을 때 펼침 기준 | 진행률 **0.35 이상**, 또는 위쪽 속도 **0.5px/ms 이상**이면 펼침. 아니면 원형으로 복귀 | 짧게 휙 올려도 펼쳐지게 |
| 반대 방향 | 펼치는 중·접는 중에도 다시 잡으면 그 자리의 진행률에서 이어서 끈다 | 위치가 튀지 않게 |
| 메뉴 끌기 시작 위치 | 점·원형·반원 배경 안에서 시작한 손가락만 메뉴 끌기로 받는다 | 사진 확대·이동, 지도 이동과 충돌 방지 |

## 5. 모션 (드래그 연동 형태 전환)

하나의 배경이 원에서 반원으로 이어서 변한다. 원과 반원을 바꿔 끼우거나 겹쳐서 흐리게 바꾸지 않는다.

| 진행률 p | 0 (원형) | 1 (반원) |
| --- | --- | --- |
| 배경 너비 × 높이 | 64 × 64 | 300 × 150 |
| 위쪽 모서리 둥글기 | 32 (높이의 절반) | 150 (높이 전체) |
| 아래쪽 모서리 둥글기 | 32 | 0 (평평) |
| 배경 아래 끝 위치 | 화면 아래에서 12 | 0 (화면 아래에 붙음) |
| 기준점 | 하단 가운데 | 하단 가운데 |

- 너비·높이·둥글기·아래 끝 위치를 모두 같은 p로 보간한다. 하단 가운데를 기준으로 좌우와 위로 넓어지며, 아래는 평평해지고 위는 둥글어진다.
- 버튼은 p에 따라 가운데(현재 화면 아이콘 자리)에서 각자 자리로 퍼진다. 위치는 p, 투명도는 p를 조금 늦춘 값, 크기는 0.6 → 1.
- 버튼 자리(하단 가운데 기준, 버튼 중심): 환율(−93, 72) · 지도(0, 122) · 번역(+93, 72) · AI(0, 42). AI만 76, 나머지는 64. 참고 이미지의 자리다(AI는 지도 이름표와 겹치지 않게 4 내림). 지금 앱(환율·번역 52, 지도 102)보다 위로 올려, 지도 이름표가 가운데 AI 버튼에 가리지 않게 했다. 이 자리면 지도 원 위 끝(154)이 반원(150) 위로 4 나오지만, 메뉴 영역(높이 160) 안이라 잘리지 않고 이름표는 반원 안에 있다(참고 이미지와 같게 둠).
- 현재 화면 아이콘과 이름은 p가 커질수록 흐려지고, 그 역할을 부채꼴 안의 강조된 현재 화면 버튼이 이어받는다.
- 놓은 뒤 자리 잡기: 약한 스프링(감쇠비 0.9 안팎, 넘침 거의 없음), 놓을 때의 속도를 이어받는다.
- 점 ↔ 원형: 지름 10 ↔ 64를 약 200ms 감속 곡선으로.
- 접기 순서: 버튼이 가운데로 모임 → 배경이 원형으로 줄어듦 → 원형이 점으로 줄어듦. 이동할 때도 같은 순서로 접으며 화면이 바뀐다.
- 애니메이션 줄이기(기기 설정 `MediaQuery.disableAnimations`, 웹 프로토타입은 `prefers-reduced-motion`)가 켜져 있으면 형태 전환과 스프링을 끄고, 상태를 바로 바꾸며 짧은 투명도 변화만 쓴다. 끄는 동안의 진행률 연동은 유지한다(손을 따라오는 것은 움직임 연출이 아니라 조작 반응이므로).

- 흰 촬영 틀이 없어지므로 "어디까지 인식하나"를 알려 줄 방법이 필요하다(지금은 틀 안만 인식). 화면 전체를 인식할지, 촬영 뒤 결과에서 범위를 보여 줄지 정해야 한다.
- 메뉴를 펼치면 양옆 버튼은 흐려지고 눌리지 않는다. 위 Tripbler 글자와 언어 바는 메뉴와 겹치지 않아 그대로 둔다.
- 프로토타입 [bottom-nav.html](bottom-nav.html)의 "번역(촬영)" 화면에 반영했다. 프로토타입의 현재 화면 버튼은 아직 예전 모양(반투명 원 위 아이콘)이며, [bottom-nav-current-button.md](bottom-nav-current-button.md)의 새 모양은 반영하지 않았다.
- 점 상태에서 누르면 촬영하지 않고 아이콘 상태로만 커진다. 촬영 화면에서 아이콘 상태일 때 이름 아래에 "눌러서 촬영"을 작게 함께 보여 준다. (2026-11-27 사용자 요청으로 "눌러서 촬영" 안내를 없앴다.)
- 부채꼴이 펼쳐지는 동안 갤러리·플래시·안내 문구는 흐려지고 눌리지 않는다. 다시 접히면 돌아온다.
- 찍은 사진을 확대·이동하는 결과 화면에서는 메뉴 배경 안에서 시작한 손가락만 메뉴로 받고, 그 밖의 두 손가락 확대·끌기는 사진이 받는다.

## 7. 접근성과 화면 크기

- 점·아이콘·버튼 모두 터치 영역 48×48 이상. 점은 화면 낭독기에 "메뉴 열기", 아이콘은 "현재 화면: 번역. 위로 끌어 메뉴 열기, 두 번 눌러 촬영"처럼 읽힌다.
- 화면 낭독기·스위치 사용자는 끌기가 어렵다. 아이콘 상태에서 "메뉴 펼치기" 접근성 동작을 제공해 끌기 없이 펼칠 수 있게 한다.
- 큰 글자: 이름 글자는 배율 1.3까지만 커지고 원형 배경 폭을 넘으면 줄여 맞춘다.
- 작은 화면(폭 320): 반원 폭 300이 화면 안에 들어가고 좌우 버튼이 잘리지 않는지 확인한다. 모자라면 반원과 버튼 간격을 폭에 맞춰 줄인다.

## 9. 구현 메모 (Flutter, 참고)

- 지금 `BottomTabBar`는 펼침 여부(bool)를 끌기 거리 24로 토글하고 `AnimatedPositioned`로 버튼을 옮긴다. 바꾼 뒤에는 상태(점/아이콘/부채꼴)와 진행률 p(0~1, `AnimationController.value`)를 두고, 끄는 동안 p를 손가락에 맞춰 직접 바꾸고, 놓으면 `SpringSimulation`으로 0 또는 1에 자리 잡게 한다.
- 배경은 p로 크기와 모서리 둥글기를 보간한 `RoundedRectangleBorder`(또는 `ShapeBorder.lerp`/`CustomPainter`)로 그린다. 버튼 위치는 `Offset.lerp(가운데, 자리, p)`.
- 화면 선택·AI 홈 이동은 지금처럼 `TabNotifier`가 맡는다. 다시 누르면 홈으로 가던 동작만 바뀐다.
- 촬영은 번역 화면이 아이콘 누르기를 받아 지금의 촬영 처리를 부르게 한다(메뉴 위젯이 카메라를 알지 않도록 콜백으로 연결).
- 파일이 450줄을 넘지 않게 상태·형태 계산(보간)·버튼 배치를 나누어 둔다.

## 10. 확장 메뉴: 면세·일정 추가 (설계, 2026-11-27, 구현 안 함)

부채꼴 메뉴에 버튼 두 개(**면세**, **일정**)를 더해, 지도 버튼을 가운데 점으로 하는 오점형(주사위 5 모양) 배치로 넓힌다. 기존 네 버튼(환율·지도·번역·AI)의 자리와 크기는 바꾸지 않는다. 프로토타입 [bottom-nav.html](bottom-nav.html)에 반영했다(2026-11-27: 펼치면 배경이 화면 전체로 커짐, 완전히 펼치는 거리 150, 폭 320에서 버튼 가로 ±87, 일정·면세는 "준비 중" 화면).

### 10-1. 결정한 것 (사용자, 2026-11-27)

- 추가 버튼: **일정**, **면세**.
- 후보였던 "경비", "소식"은 넣지 않는다. 소식은 메뉴 버튼보다 AI 홈 카드·알림이 맞고, 면세 화면 위 배너로 규정 변경을 알린다.
- 면세 금액은 사용자가 말·글·영수증으로 넣는다. **은행·카드 앱 연결은 하지 않는다**(카드 내역으로는 들고 오는 물건과 품목을 구분할 수 없고, 현금 구매가 빠지며, 허가·보안·비용 부담이 크다).

### 10-2. 버튼 자리

하단 가운데 기준, 버튼 중심. 지도를 가운데 점으로, 아래 두 점(환율·번역)을 지도 높이 기준으로 위로 뒤집은 자리에 새 버튼을 둔다.

```
     [면세]          [일정]        ← (−93, 172) / (+93, 172)  새로 추가
              [지도]               ← (0, 122)
  [환율]                [번역]     ← (−93, 72) / (+93, 72)
              ( AI )               ← (0, 42)
```

| 버튼 | 자리 | 크기 | 아이콘(초안, Material) | 이유 |
| --- | --- | --- | --- | --- |
| 면세 | (−93, 172) 왼쪽 위 | 64 | `shopping_bag` | 환율과 같은 쪽(금액·환산과 이어짐) |
| 일정 | (+93, 172) 오른쪽 위 | 64 | `event_note` | 지도·장소와 이어짐 |

- 이름표 모양은 다른 버튼과 같다(원 아래 가장자리에 걸친 흰 꼬리표). 새 버튼 이름표 아래 끝은 약 132로, 지도 원 위 끝(154)보다 낮고 지도 원과 겹치지 않는지 큰 글자에서 확인한다.

### 10-3. 배경: 원 → 화면 전체 (2026-11-27 사용자 요청으로 변경)

- 펼칠 때 반투명 배경이 **화면 전체로 커진다.** 현재 화면 버튼의 원(중심이 아래에서 44)을 중심으로 하나의 원이 커져 화면 네 모서리까지 덮는다(반지름 32 → 화면 모서리까지 거리, 폭 340·높이 740 화면에서 약 718).
- 화면 가장자리가 원을 잘라, 커지는 동안 아래는 평평하고 위는 둥근 모양으로 보인다. 원과 다른 모양을 바꿔 끼우지 않고 하나의 원이 이어서 커진다.
- 반지름은 끌기 진행률 p에 처음과 끝을 부드럽게 한 곡선(smoothstep)을 걸어 키운다. 버튼 위치·투명도는 지금처럼 p에 그대로 연결한다.
- **접을 때(들어가는 동작)는 지금과 같다:** 버튼이 가운데로 모이고, 배경이 원으로 줄어든 뒤 점이 된다. 같은 원이 거꾸로 줄어든다.
- 이전 설계(펼친 모양을 324×264 아치로)는 이 방식으로 바뀌었다. 버튼 배치 폭 324(작은 화면 304)는 버튼 가로 간격 기준으로만 남는다.
- 펼친 동안 화면 내용과 번역 카메라 화면의 위 Tripbler·언어 바는 반투명 배경 아래로 흐리게 비친다.
- 화면 전체 = SafeArea 안쪽 본문이다. 상태 표시줄·제스처 바 영역은 덮지 않는다(2026-11-27 구현).

### 10-4. 펼치는 방식

- **한 번 끌어 6개를 모두 펼친다.** 두 단계(먼저 4개, 더 끌면 2개)는 새 버튼을 찾기 어려워 쓰지 않는다.
- 배경이 커진 만큼 완전히 펼치는 거리를 120 → **150**으로 늘린다. 놓을 때 펼침 기준(진행률 0.35 이상, 위쪽 속도 0.5px/ms 이상)은 그대로.
- 버튼은 가운데에서 각자 자리로 퍼진다. 새 버튼은 이동 거리가 가장 길어, 투명도를 조금 늦게(p 0.3부터) 올려 퍼지는 순서가 자연스럽게 보이게 한다.
- 끌기 영역(펼친 상태)은 화면 전체다. 어디서든 아래로 끌면 진행률이 줄어 접히고, 버튼이 아닌 빈 곳을 누르면 이동 없이 점으로 접힌다(배경이 화면 전체라 "메뉴 바깥"이 따로 없다).

### 10-5. 화면 이동

- `TabNotifier`의 탭은 지금 3개(환율 0·지도 1·번역 2) + 홈(AI, −1)이다. 면세와 일정을 탭으로 더한다(예: 일정 3, 면세 4). 인덱스와 화면 순서는 구현 때 정한다.
- 일정·면세 화면은 아직 없으므로 처음에는 "준비 중" 화면으로 연결하고 메뉴 배치부터 확인한다.
- 현재 화면 재선택은 접기만 하고, 홈은 AI 버튼으로만 간다는 규칙은 그대로다.

### 10-6. 면세 화면이 할 일 (1차 범위)

| 우선 | 기능 | 재료 |
| --- | --- | --- |
| 1 | 금액을 말·글로 넣으면 달러로 바꿔 합산하고, 기본 한도(1인 800달러, 서버 규칙 기준)까지 남은 금액과 현지 통화 환산을 보여 줌. 넘으면 예상 세금과 자진신고 감면 안내 | 서버 면세 규칙 + 기존 환율 API |
| 2 | 영수증·가격표를 찍어 품목·금액을 채움(애매한 줄은 "확인 필요") | 기존 기기 글자 인식·가격 뽑기 |
| 3 | 일정의 귀국 전날 "지금까지 ○달러, ○달러 남음" 알림, 한도 90% 알림 | 일정 + 산 물건 목록 |
| 나중 | 술·담배·향수 별도 계산, 현지 택스리펀드 기준 | 규칙 데이터 정리 뒤 |

- AI 버튼으로 "이 가방 3만 8천 엔인데 면세 돼?", "남은 한도로 얼마까지 살 수 있어?"처럼 물으면 면세 화면에 바로 반영한다.
- 면세 규칙은 서버에서 받는다(예: `GET /api/v1/duty-free/rules`, 기준일 포함). 관세청 공식 API는 확인하지 못해, 규칙은 서버 데이터로 두고 바뀌면 고친다. 화면에 기준일·관세청 안내 링크·"참고용"을 함께 보여 준다.
- AI는 서버 규칙과 앱 환율로만 계산하고 숫자를 지어내지 않는다. 통화가 애매하면 먼저 묻고, 세관 신고를 대신 하지 않는다.
- 산 물건 목록은 처음에는 기기에 저장한다. 영수증 사진은 기기에서 읽고 서버에는 읽은 글자만 보낸다.

### 10-7. 정할 것

- 작은 화면(폭 320): 버튼 가로 간격을 304/324 비율(±87)로 줄일지(프로토타입은 줄임).
- 면세·일정 아이콘과 탭 인덱스.
- 화면 전체 배경의 진하기: 지금 반투명(청회색 72%)이면 아래 화면이 꽤 비친다. 버튼이 잘 보이게 더 진하게 할지.
- 번역 화면 예외(2절: 바깥을 눌러도 현재 화면 버튼 상태 유지)를 화면 전체 배경에서 "빈 곳 누르기"에도 그대로 적용할지.
- 현재 화면 버튼의 새 모양([bottom-nav-current-button.md](bottom-nav-current-button.md))과 함께 쓸 때 가운데(AI) 자리와 겹치지 않는지.

### 10-8. 완료 조건 (구현 때)

- [ ] 한 번 끌어 6개가 모두 퍼지고, 기존 네 버튼의 자리·크기가 그대로다.
- [ ] 배경이 원에서 화면 전체로 이어서 커지고, 접을 때는 버튼 모임 → 원 → 점 순서로 줄어든다. 새 버튼 이름표가 지도 버튼과 겹치지 않는다(글자 배율 1.3·2.0 포함).
- [ ] 펼친 상태에서 빈 곳을 누르면 이동 없이 접히고, 어디서든 아래로 끌면 접힌다.
- [ ] 폭 320에서 버튼이 화면 밖으로 나가지 않는다.
- [ ] 면세·일정 버튼은 각 화면(처음에는 준비 중 화면)으로 이동하며 점으로 접힌다.
- [ ] 번역 카메라 화면의 위 Tripbler·언어 바, 아래 갤러리·플래시와 겹치지 않는다.
